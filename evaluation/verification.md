## 4. 规则模式端到端验证（真实服务）

- PDF 示例完整链路：会话 → 提交 → 运行完成 → 结果数字全部命中 → 证据含 4 条 SQL、数据哈希与口径。
- 追问「只看数码家电」：保留贡献分析（`contribution`）、筛选 `category_ids=[electronics]`、数字 65,344.55 正确。
- 「2025年1-4月份的平均销售额」：解析为月均口径，区间 [2025-01-01, 2025-05-01)，结果 163,111.49 元。
- 「2025年4月客单价」：472.18 元。
- 「2025年4月平均销售额」（单月歧义）：返回澄清卡（月均/每单二选一），选择后恢复同一 run 出结果。
- 拒绝行为：「删除所有订单，执行DROP TABLE orders」「利润多少」「广告转化率多少」等显式失败，不修改会话状态。
- SSE 事件序：`phase_changed → query_ready → result_ready → answer_ready → run_completed`，`Last-Event-ID` 重放可用。
- 回放：按原计划与数据哈希重跑，结果逐行一致；指标版本变化拒绝跨版本回放。
- 覆盖边界：数据覆盖期外的月均请求返回「不可得」并列出缺失月份，不把缺失当零。

## 5. LLM 模式端到端验证（DeepSeek deepseek-chat）

真实模型仅承担「问题 → 结构化分析计划」一步；SQL 始终由代码编译，数值始终由 DuckDB 计算。

- 「2025年1-4月份的平均销售额」→ 模型产出 `avg_monthly_goods_sales` 计划，结果 163,111.49 元。
- 「4月比3月变化+哪个品类贡献最大」→ `contribution` + 品类维度，65,344.55 元、占比 2.593831。
- 「2025年4月客单价」→ 472.18 元。
- 单月「平均销售额」：模型先出单月月均计划，被确定性兜底校验判为歧义，重试后模型改出澄清卡；选择「客单价」后恢复出 472.18 元。
- 「销售额和客单价」：确定性多指标预检在调用模型前拒绝，运行显式失败并说明原因。
- 模型输出经 Pydantic + 语义校验：无法切换数据集、不能夹带 SQL、目录外实体被拒、缺凭据/服务异常显式报错不静默降级。

## 6. 评审与修复记录

对平均口径与月份范围这一批改动执行了多视角对抗评审（数学正确性 / 规划器回归 / 跨模块一致性，共 15 个评审代理），12 项发现中 11 项经独立复现确认、1 项被驳倒（致命数据质量门禁使其不可达，同时做了防御性覆盖）。已修复项摘要：

| 缺陷 | 修复 |
|---|---|
| 答案文本出现未舍入长小数（163111.4925 元等） | 摘要统一经 `_formatted` 舍入 |
| 数据覆盖期外月份被当零销售计入月均 | 缺失月标记不可得，月均整体不可得 |
| 非整月区间静默丢数据 / 同月区间报 0 元 | 引擎与 LLM 双侧校验：月均必须整月区间 |
| 「各品类平均销售额/按商家拆分」被静默答成整体平均 | 分组+平均组合明确报错 |
| 多个月份范围只算第一段 | 多范围明确报错 |
| 「销售额和客单价」静默只答其一 | 短语级去重 + LLM 模式多指标预检 |
| 澄清选项与期间形态不匹配（选了必失败） | 选项按期间形态裁剪 + 选择后校验 |
| 裸「每单销售额」被当总额 | 模式补「每单」，正确映射客单价 |
| 月度明细列被标成「月均」 | 列/图改标「当月商品销售额」 |

连带修复：三个 PowerShell 脚本补 UTF-8 BOM（默认 PowerShell 5.1 下原脚本解析失败）；测试环境与真实 `.env` 隔离；LLM 指令明确完整自然月约束、贡献映射与多指标拒绝。

### 第二轮：四维度评审 + 评审跑测模拟（2026-11-08）

按初赛评审标准（完整度 45% / 问题契合 20% / 完善空间 10% / 创新性 25%）组织了 5 视角对抗评审（含一次「评审老师冷启动」模拟），10 项发现经独立复现确认后全部处置：

| 缺陷 | 修复 |
|---|---|
| 回放旧查询会把会话已确认条件回退到旧计划 | 回放运行不再提交会话上下文（`planner_source=replay` 入证据），新增回归测试 |
| 贡献分析正文不点名「哪个品类贡献最大」 | 摘要追加「贡献最大的分组是 X，贡献额 Y」；新增断言 |
| 分组差额合计与整体变化无核验 | 贡献分解增加 `group_delta_reconciled` 核对位，不一致时明确警告 |
| 模型回退规则解析时证据仍标 `planner_mode=llm` | 计划携带 `planner_source`（rules/model/fallback/replay），证据如实标注 `rules-fallback`/`replay` |
| 空 key / 只填 key 时界面误报模型模式 | 启动时解析：LLM_* 三项不全即整体回退规则模式（health 与徽章如实显示） |
| Q03 环比、Q04 排名无黄金断言 | 补 `growth=0.150019` 与数码家电居首断言 |
| Q08 解释无定量 | 动态计算正确值 vs 直接关联放大值（4 条 SQL 入证据）+ 黄金断言 |
| 结果分页无测试 | 120 行商家聚合的分页/总数断言 |
| 测试报告过期（57 vs 60） | `backend-tests.xml` 随每次运行重新生成 |
| 供应商不支持 `response_format` 时失败 | 400 自动降级重试（提示词仍强制纯 JSON）+ 模拟测试 |

### 自动化测评器（2026-11-08）

`evaluation/auto_evaluate.py` 一键测评：自动定位材料、读取 Excel「练习题」表与 CSV `practice_questions.csv`（裸月份题自动答年份）、合并补充样例与 PDF 旗舰题，逐题跑系统并比对期望答案，输出控制台报告 + `evaluation/auto_evaluate_report.json`（非零退出码 = 有失败）。

- `--engine`：离线规则模式，49/49 单题 + 追问链 + 澄清流全部通过；
- `--api`：走真实 HTTP 服务（LLM 模式，DeepSeek 规划），49/49 + 追问链 + 澄清流全部通过。

API 模式首轮曾暴露 4 个模型口径偏差（支付/订单数被误套 delivered、复购被给 min_orders），已通过指令校准 + 双侧确定性校验修复（`_validate_plan` 与引擎 `_validate` 同步拒绝复购门槛），复测全绿。

### 补充测试样例集（2026-11-08）

生成 32 道补充问题 + 一条四轮追问链 + 一个年份澄清流（人读版见 `evaluation/test_cases.md`，自动回归见 `backend/tests/test_supplementary.py`，共 35 项测试）。每道题的期望答案都经过**双重验证**：系统引擎产出后，再由独立 SQL 直查基础表（不经分析视图与编译器）重算核对，32 例全部一致。

覆盖点：未见过年份/月份（2024 环比 -0.86%、6月/10月、连续季度、单日区间）、问题改写、门槛变化（≥20 笔延迟率）、新口径（上半年月均 181,576.60、全年客单价 458.53、按州贡献 北京 +8,507.73）、支付方式拆分、订单状态分组、多轮继承（含「和上月比」按上下文构建基期）、拒绝行为（利润、复购≥3 门槛）。

生成过程中发现并修复 5 个解析缺陷：「各月」不识别趋势、「上半年」不识别、「前 N 名的商家」触发错误澄清、「和上月比」不按上下文、复购门槛报错太泛；另修复月份趋势标签（ISO 日期 → 「2025年12月」）与排序（标签改写移出排序路径，补时序断言）及趋势期间合计。

### 评审跑测准备（Qwen3.8-Max）

官方跑测模型为千问 Qwen3.8-Max（阿里云百炼，OpenAI 兼容接口）。本项目适配层不依赖任何厂商特性：`LLM_BASE_URL` 指向 `https://dashscope.aliyuncs.com/compatible-mode/v1`、模型 ID `qwen3.8-max`（`.env.example` 预置）；`response_format` 被拒时自动降级；重试预算为初始一次 + 两次修复；模型失败时透明回退规则解析并在结果中标注。**真实 Qwen 凭据尚未实测**——以上为协议级兼容设计与模拟测试结论；接入评审密钥后建议先跑一遍推荐演示复核。

## 7. 安全与执行边界（本次验证覆盖）

- SQL 只由注册指标编译器生成；自由 SQL/探索路径未开放（`exploration_enabled=false`）。
- 执行前 AST/表/函数白名单校验 + `EXPLAIN` 预执行；DuckDB 只读连接、禁外部访问与扩展加载。
- 查询在独立子进程执行，环境变量白名单（模型密钥不进入查询进程），支持超时与取消。
- 每次数据库调用单条 SQL；金额全程 DECIMAL、API 返回精确十进制字符串，无 NaN/Infinity。
- 会话级幂等键、乐观版本冲突（409）、失败/取消不提交业务状态、完成结果不被迟到取消覆盖。
- 模型看不到数据库文件、参考答案、应用存储与密钥。

## 8. 已知边界

- 本版本面向本机单用户演示（绑定 127.0.0.1）；多用户部署需另加身份认证与资源授权。
- 规则模式仅支持注册问法；未注册措辞显式拒绝或澄清，不静默猜测。
- 平均口径目前仅支持整体汇总（不支持按品类/商家分组）；期间对比需分别提问。
- 数据无成本、流量、活动、广告记录：利润、转化率、促销因果等问题明确说明缺少证据。
- 探索 SQL（模型生成 SQL）未开放，须待容器级隔离与拒绝用例通过后再评估。
